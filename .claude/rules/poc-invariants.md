# PoC数据可信度约束
这些约束优先于开发便利。违反任何一项都可能使PoC数据失效。
## 1. 工具模式上下文隔离
工具模式模型请求只能包含：
- 静态工具模式System Prompt
- 当前工具任务内的候选人输入
- 当前工具任务内的AI回复
不得包含：
- 候选人姓名
- 问卷结果
- 考官模式历史
- 其他工具任务历史
- 评分标准、阶段目标或测评意图
- assessmentId等可识别业务元数据
`buildToolContext()` 必须同时过滤：
- `mode = tool`
- `taskId = 当前任务`
工具模式System Prompt不得进行变量插值。
## 2. A结论锁定
状态为以下任一值时，A仍处于锁定状态：
- `pending_interview`
- `final_evaluating`
锁定期间，常规面试官接口不得返回：
- A的等级
- A的轨道
- A的置信度
- A的维度评估
- A的判断理由
- 落差、红线或其他可能泄露判断倾向的结果
不能只依靠前端隐藏。
B提交后不能立即解锁；只有C成功产出、状态进入`completed`后才能展示A/B/C。
## 3. signals不下发
模型的阶段信号只用于：
- 后端状态机
- 数据库存储
- 离线PoC数据导出
不得进入候选人端或面试官端常规API。
不要新增HTTP导出接口，除非该接口已写入正式API文档。
## 4. 模型调用唯一出口
所有模型调用必须经过统一LLM客户端。
每次调用必须：
1. 调用前落库完整请求消息
2. 成功后落库原始响应
3. 失败后落库错误信息
4. 保留模型名、用途、token和耗时信息
禁止使用托管会话、应用编排或智能体能力。
## 5. 后端控制流程
模型只能返回已定义Schema中的信号。
阶段推进、S1.3触发、任务切换和状态变化必须由后端执行。
不要读取未在PRD Prompt Schema中定义的信号，例如 `candidate_stuck`，除非先完成正式需求变更。
